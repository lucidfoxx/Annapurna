# SharePlate Frontend

React + JavaScript + Vite + Tailwind CSS frontend for the SharePlate food-rescue platform.

## Features

- Overview dashboard with network metrics and recent food listings
- Food listing search, status filters, create listing and request food
- Donation request review with accept/reject actions
- Volunteer handover workflow with pickup and delivery confirmation
- Community impact dashboard
- Login and registration screens
- Responsive layout for desktop, tablet and mobile
- Centralized Axios client with JWT bearer token support
- Vite proxy to the local FastAPI backend

## Stack

- React 18
- JavaScript (JSX)
- Vite
- Tailwind CSS v4
- React Router
- Axios
- Lucide icons

## Requirements

- Node.js 20.19+ (or Node 22 LTS)
- npm
- SharePlate FastAPI backend running on `http://127.0.0.1:8000`

## Setup

Extract the ZIP, then:

```bash
cd SharePlate_Frontend
npm install
cp .env.example .env
npm run dev
```

Open the URL printed by Vite, normally:

```text
http://localhost:5173
```

The Vite development server proxies `/api` requests to `http://127.0.0.1:8000`.

## Run backend and frontend

Terminal 1:

```bash
cd ~/Downloads/SharePlate_Backend
sudo systemctl start mysql
uv run uvicorn app.main:app --reload
```

Terminal 2:

```bash
cd ~/Downloads/SharePlate_Frontend
npm run dev
```

Backend Swagger docs:

```text
http://127.0.0.1:8000/docs
```

## Production build

```bash
npm run build

```

## API integration notes

The frontend centralizes API paths in `src/lib/api.js`. It currently expects the backend API prefix `/api` and these routes:

| Feature | Expected endpoint |
|---|---|
| Register | `POST /api/auth/register` |
| Login | `POST /api/auth/login` |
| Current user | `GET /api/auth/me` (optional) |
| Food listings | `GET, POST /api/listings` |
| One listing | `DELETE /api/listings/{id}` |
| Donation requests | `GET, POST /api/requests` |
| Accept/reject request | `POST /api/requests/{id}/accept` or `/reject` |
| Handovers | `GET /api/handovers/available` or `/my` |
| Assign/pickup/deliver | `POST /api/handovers/{id}/assign`, `/pickup`, `/deliver` |
| Impact | `GET /api/extras/impact` |

**Important:** The UI is wired to the route conventions above based on the SharePlate backend starter. Confirm exact request/response schemas and paths in `http://127.0.0.1:8000/docs`. If a route differs, update its path or payload in the page or in `src/lib/api.js`. Error messages from FastAPI are shown in the UI to make mismatches easier to diagnose.

The login request uses form-encoded `username` and `password`, as expected by FastAPI's `OAuth2PasswordRequestForm`. If your backend login route accepts JSON instead, change the `login` function in `src/context/AuthContext.jsx`.

Registration currently sends `full_name`, `email`, `password`, and `role`. Adjust these field names to match the backend's Pydantic registration schema if needed.

## Environment

`.env.example`:

```env
VITE_API_BASE_URL=/api
```

When using the Vite proxy, keep `/api`. For a separately hosted API, set an absolute URL and configure backend CORS accordingly.

## Notes

- The frontend does not store application records in browser storage. Listings and metrics are fetched from the API.
- JWT tokens are stored in `localStorage` for this local MVP. Consider secure cookie-based authentication and additional protections before production deployment.
- Registration deliberately omits the admin role. Admin accounts should be created through a trusted administrative process.
- Some impact fields are read with fallback names because backend response schemas may evolve.
